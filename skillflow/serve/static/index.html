        快速开始
        ▾
      

      

        

          
核心流程

          

            创建/上传技能
            →
            评估得分
            →
            演化优化
            →
            应用最佳版本
          

        

        

          
Spec YAML 字段说明

          

            
字段必填说明

            
              
description是技能的一句话功能描述，决定了技能的行为边界

              
scene是适用场景列表，支持多个场景，影响测试用例的覆盖范围

              
input_output.input是用户输入的格式描述

              
input_output.output是期望输出的格式描述

              
rule否技能必须遵守的行为规则列表。规则越清晰，技能表现越稳定

              
example否输入输出示例，帮助模型理解预期行为

              
reference否外部参考文档路径。大段参考资料建议拆到独立文件

            
          

        

        

          
创建方式

          
    
            
  • YAML 编辑器：在 Create 页面填写 Spec 并创建，适合从零开始
    • 
            
  • 上传 ZIP：上传已有的技能目录（ZIP 包），必须包含 SKILL.md 文件
    • 
          

        

        

          Spec 的质量直接影响生成技能的质量。建议 rule 和 example 尽可能具体，模糊的描述会导致技能行为不确定。
        

      

    


    

      

        评估技能 (Eval)
        ▾
      

      

        

          
操作步骤

          
    
            
  1. 从下拉框选择要评估的技能
    2. 
            
  2. 可选：选择一个 Spec 作为评估参照（不选则使用技能自带信息）
    3. 
            
  3. 生成或编辑测试用例
    4. 
            
  4. 设置参数后点击「运行评估」
    5. 
          

        

        

          
参数说明

          

            
参数默认值说明

            
              

                trials5
                每个测试用例的运行次数。次数越多结果越稳定，但消耗的 API 调用量和时间也线性增加。
建议：快速验证用 3 次，正式评估用 5 次		
              

              

                parallel1
                并行执行数。增大可加速评估，但同时会增加 API 并发压力。若 API 有速率限制请谨慎调高
              

            
          

        

        

          
测试用例

          
    
            
  • 系统根据 Spec 和技能内容自动生成测试用例
    • 
            
  • 生成后可在界面上查看、编辑，再启动评估
    • 
            
  • 也可选择已保存的测试用例，或手动上传自定义用例文件
    • 
          

        

        

          
评分维度

          
每项独立评分，综合判定是否通过。单条用例满分 1.0，≥ 0.8 为通过。

          

            
维度说明

            
              
相关性回答是否切题，有无答非所问

              
准确性事实是否正确，有无 AI 幻觉

              
完整性是否覆盖关键信息，有无遗漏

              
逻辑性内容结构是否清晰，有无逻辑混乱

              
语言质量表述是否自然得体

              
意图预判是否擅自预判用户意图、添加未要求的内容

              
风险合规是否包含不当或有风险的内容

            
          

        

        

          首次评估建议先观察各维度的得分分布，找到短板后再针对性优化，而不是直接进入演化。
        

      

    


    

      

        演化优化 (Evolve)
        ▾
      

      

        

          
演化流程

          
每轮演化自动执行以下步骤：

          

            审视当前技能
            →
            识别问题并改进
            →
            用测试用例评估
            →
            对比提升幅度
            →
            决定采纳或拒绝
          

          
被拒绝的改进会被丢弃，技能回退到上一版本；被采纳的改进成为新的最优版本。

        

        

          
参数说明

          

            
参数默认值说明

            
              

                threshold0.01
                每轮最低提升幅度。提升低于此值的改进会被拒绝，用于过滤偶然波动。
设得过高会导致大部分改进被拒绝，演化停滞；设得过低会接受无意义的微小波动。
建议：0.01 ~ 0.03		
              

              

                speedlow
                演化激进程度，控制每轮修改点数量和改动范围。low=1~3个修改点，medium=3~6个，high=不限制
              

              

                modesteady
                演化模式。详见下方模式说明
              

              

                iterations100
                最大演化轮数。达到上限后停止，无论是否还有改进空间。
每轮都会消耗 API 调用，轮数越多总耗时越长		
              

              

                patience10
                连续多少轮无提升后停止。用于避免在进入瓶颈后继续无效演化。
如果预期技能还有较大改进空间，可适当调高		
              

              

                trials5
                每个测试用例的运行次数。与评估中的 trials 含义相同，越高越稳定但耗时越长
              

            
          

        

        

          
Speed 档位说明

          

            
档位范围行为

            
              
保守≤ 0.3每轮只修复明确的单个问题，改动最小。适合微调已有技能

              
均衡0.3 ~ 0.6允许局部调整和补充。适合技能结构基本正确但需要完善细节的场景

              
激进> 0.6允许重组流程、重写段落。适合技能质量较差需要大改的场景

            
          

          

            speed 越高单轮改动越大，但不等于效果越好。大幅改动可能导致回退，反而降低通过率。建议从 low 开始，确认演化方向正确后再切到 medium 或 high。
          

        

        

          
演化模式

          

            
模式说明

            
              
steady每轮都从基线版本出发，改动更可控，适合探索不同优化方向

              
greedy每轮从当前最优版本出发，收敛更快，但可能走入局部最优

            
          

        

        

          
结果表格解读

          

            
列含义

            
              
当前最优截至本轮的最佳通过率

              
本轮得分本轮演化后技能的通过率

              
提升幅度本轮相比当前最优的提升值（负数表示回退）

              
ACCEPTED提升幅度 ≥ threshold，已采纳为新的最优

              
REJECTED提升幅度 < threshold，已拒绝，技能回退

            
          

        

        

          
版本管理

          
    
            
  • 查看 Diff：选择任意两个版本，查看具体改动内容
    • 
            
  • 下载 ZIP：将指定版本导出为 ZIP 文件
    • 
            
  • 应用版本：将指定版本替换当前技能目录（会自动备份当前版本，可恢复）
    • 
          

          

            应用版本前建议先用 Diff 确认改动内容，避免引入不符合预期的变更。
          

        

      

    


    

      

        常见问题
        ▾
      

      

        

          
评估通过率很低，怎么办？

          
    
            
  • 查看各维度得分，找到得分最低的维度作为突破口
    • 
            
  • 检查 Spec 中的 rule 和 example 是否足够具体
    • 
            
  • 如果是语言质量问题，考虑调整 Spec 中的表述风格要求
    • 
          

        

        

          
演化一直被 REJECTED，可能的原因？

          
    
            
  • threshold 设置过高 — 尝试降低到 0.01
    • 
            
  • speed 过高导致改动过大产生回退 — 切换到 low 再试
    • 
            
  • 技能可能已接近最优 — 尝试增加测试用例覆盖更多场景
    • 
            
  • patience 用尽但仍在改进 — 适当调高 patience
    • 
          

        

        

          
如何锁定测试用例？

          
    
            
  • 首次评估生成测试用例后，点击「保存」可保存当前用例
    • 
            
  • 后续评估和演化可选择已保存的测试用例，避免重新生成
    • 
            
  • 如需重新生成，勾选「忽略缓存」选项
    • 
          

        

        

          
speed 应该设多少？

          
    
            
  • 不确定时用默认值 low（保守模式，1~3 个修改点）
    • 
            
  • 技能刚创建、质量较差时可以尝试 medium（3~6 个修改点）
    • 
            
  • 需要大幅度重组或改写时使用 high（不限制修改点）
    • 
            
  • 技能已打磨到较高水平时，用 low 做精细调整
    • 
          

        

        

          
评估和演化消耗多少 API 调用？

          
    
            
  • 单次评估 ≈ 测试用例数 × trials 次调用（评估）+ 1 次调用（生成用例，仅首次）
    • 
            
  • 单轮演化 ≈ 1 次调用（审视）+ 评估调用量 + 可能的反思改写调用
    • 
            
  • 总调用量 ≈ 单轮调用量 × iterations 轮数
